# Учебный проект «Личный финансовый менеджер»

## О проекте

Учебный проект на Python, созданный для изучения и практического закрепления принципов объектно-ориентированного программирования (ООП).

В рамках проекта реализована простая модель управления личными финансами, которая позволяет создавать счета, пополнять и списывать средства, переводить деньги между счетами и вести историю финансовых операций.

**Цель проекта** — получить практический опыт работы с классами, объектами, инкапсуляцией, наследованием, полиморфизмом, абстрактными классами и перегрузкой операторов.

Проект завершён в рамках учебной задачи. Дальнейшее развитие функционала не планируется, поскольку основная цель — обучение ООП — достигнута.

## Что реализовано

- **Класс `Account`** — хранение названия счёта, владельца и текущего баланса.
- **Класс `Transaction`** — абстрактный базовый класс для финансовых операций, содержащий сумму, дату и описание операции.
- **Класс `Income`** — реализация операции пополнения счёта.
- **Класс `Expense`** — реализация операции списания средств со счёта.
- **Класс `Transfer`** — перевод средств между двумя счетами с проверкой достаточности баланса и запретом перевода на тот же счёт.
- **Класс `FinanceManager`** — управление счетами и историей успешных финансовых операций.
- **Инкапсуляция и свойства** — защита внутренних атрибутов и проверка корректности названия счёта и баланса.
- **Валидация финансовых операций** — проверка положительности суммы операции с помощью статического метода.
- **Обработка ошибок** — использование `ValueError` при создании объектов с некорректными данными.
- **Контроль выполнения операций** — добавление операции в историю только при успешном выполнении.
- **Ограничение количества счетов** — использование атрибута класса для определения максимального количества счетов.
- **Строковое представление объектов** — вывод информации о счетах и финансовых операциях.
- **Перегрузка операторов** — сравнение финансовых операций, проверка их истинности, поиск операции в менеджере и получение операции из истории по индексу.
- **Демонстрация работы программы** — создание счетов, выполнение финансовых операций и вывод балансов и истории в функции `main()`.

## Изученные темы ООП

В ходе работы над проектом были практически применены следующие концепции:

- Создание классов и объектов.
- Использование конструктора `__init__()`.
- Инкапсуляция данных с помощью атрибутов с двойным подчёркиванием.
- Создание свойств с помощью `@property` и сеттеров.
- Работа с методами экземпляров.
- Использование статических методов через `@staticmethod`.
- Использование атрибутов класса.
- Наследование одного класса от другого.
- Вызов конструктора родительского класса через `super()`.
- Переопределение методов в дочерних классах.
- Применение полиморфизма при выполнении различных типов финансовых операций.
- Создание абстрактного класса с помощью `abc.ABC`.
- Использование абстрактных методов через `@abc.abstractmethod`.
- Формирование строкового представления объектов с помощью `__str__()`.
- Перегрузка операторов сравнения `__eq__()`, `__lt__()` и `__gt__()`.
- Переопределение `__bool__()` для определения истинности объекта.
- Реализация `__contains__()` для проверки наличия операции в истории.
- Реализация `__getitem__()` для доступа к операциям по индексу.
- Организация взаимодействия между несколькими классами и работа со списками объектов.

## Итоги обучения

В результате выполнения проекта получен практический опыт проектирования небольшого приложения для управления личными финансами с использованием ООП.

Удалось закрепить создание классов и объектов, научиться скрывать внутренние атрибуты, организовать наследование и переопределение методов, а также выстроить взаимодействие между несколькими классами.

Отдельно была отработана работа с абстрактными классами и методами, применение полиморфизма, использование статических методов и атрибутов класса, а также перегрузка специальных методов Python.

В ходе разработки также были реализованы проверки корректности данных, обработка неудачных финансовых операций и ведение истории успешно выполненных операций.

Некоторые аспекты, такие как более строгая проверка принадлежности счетов менеджеру, выбор семантики равенства финансовых операций и дальнейшее совершенствование обработки ошибок, могут быть улучшены в будущем, однако не являются обязательными для завершения учебной задачи.

**Вывод:** проект выполнил свою учебную задачу — позволил применить основные принципы ООП на практике, изучить дополнительные возможности Python и получить опыт проектирования приложения с несколькими взаимодействующими классами.
